# 开发环境初始化（种子数据建议）

本文件用于快速搭建一个可测试流程：

- 菜品库
- 开单
- 客人下单（配送/自取）
- 生产进度
- 履约执行
- 开单复盘

## 1. 管理员配置

在 `system_admins/main` 写入你的店主 openid：

```json
{
  "_id": "main",
  "adminOpenIds": ["你的openid"]
}
```

## 2. 运行态初始化

`system_runtime_state/main`：

```json
{
  "_id": "main",
  "currentSaleId": null
}
```

## 3. 起送价规则（可选）

`delivery_rules/main` 示例：

```json
{
  "_id": "main",
  "defaultMinCents": 2000,
  "cityRules": [
    { "city": "paris", "minCents": 2500 },
    { "city": "rueil-malmaison", "minCents": 2000 }
  ]
}
```

## 4. 建议测试菜品（店主端创建）

至少创建 3 个菜品：

1. 一个有图片的菜（测试列表与详情图）
2. 一个低价菜（便于测试起送价不足）
3. 一个可快速售罄的菜（测试库存逻辑）

建议字段：

- 名称
- 价格（EUR）
- 描述
- 上架状态

## 5. 建议测试场景组合

### A. 纯配送开单
- 创建 sale
- 设置配送时间段
- 配置 2~3 个菜库存
- 顾客下配送单

### B. 纯自取开单
- 顾客仅自取（不填地址，填电话）
- 测试自取执行页状态切换

### C. 混合开单
- 同时有配送和自取订单
- 测试：
  - 交付准备（配送排序、自取不排序）
  - 配送执行 / 自取执行分流
  - 完成本次开单校验（配送+自取都要已交付+已收款）

## 6. 回归清单（最小）

- 店主身份识别
- 开单 / 截单 / 备单完成 / 完成开单
- 客人配送下单 / 自取下单
- 客人改单 / 取消单
- 店主改单 / 取消单 / 待确认单处理
- 开单复盘
